# ADR-008 — Palette uniqueness: OKLab perceptual distance replaces hue-angle check

**Status:** Accepted

## Context

The test suite enforces that no two same-type themes are perceptually indistinguishable, so contributors cannot accidentally (or deliberately) add a theme that is a near-copy of an existing one.

The original implementation checked the HSL hue angle of each theme's `primary` token. If two same-type themes had primary tokens within 10° of each other, the pair failed — unless it was in a `KNOWN_CLOSE` exception set.

This approach had two compounding problems:

**Problem 1 — hue angle is a poor perceptual metric.** HSL hue ignores saturation and lightness entirely. A near-grey color (`#C0C8D4`, hue 216°) and a vivid ultramarine (`#5078F0`, hue 225°) are 9° apart in hue — the test would flag them as too similar — but they are visually distinct: one is a washed-out neutral, the other is a saturated blue. Conversely, two rich warm ambers at hue 35° and 42° may genuinely look the same but pass the test if they happen to sit 11° apart.

**Problem 2 — single-token check forces false positives.** Comparing only the primary token misses the full picture. Two themes can share primary territory but diverge substantially via accent or muted (for example, Cordovan uses a steel-blue accent while Ember uses an orange-red accent — these are visually distinct themes despite similar primary hues). Under the hue-only rule, such pairs required grandfathered exceptions. The `KNOWN_CLOSE` set grew to 35 entries, many of which documented themes that are not actually close.

## Decision

Replace the hue-angle uniqueness check with an OKLab perceptual distance check across three tokens simultaneously.

**Color space:** OKLab (Björn Ottosson, 2020). OKLab is a perceptually uniform color space built on the LMS cone model. Equal Euclidean distances in OKLab correspond to approximately equal perceived color differences. One OKLab unit ≈ 50 just-noticeable-differences (JNDs); ΔE = 0.02 ≈ 1 JND.

**Tokens checked:** `primary`, `accent`, and `muted`. Error tokens are not included because they are almost always a standard red across themes and would not provide meaningful distinctiveness signal.

**Pass condition:** a theme pair passes if **at least one** of `dPrimary`, `dAccent`, or `dMuted` is ≥ `MIN_DIST`. Equivalently, a pair fails only if **all three** distances are below `MIN_DIST`. This AND logic means:

- Themes sharing primary territory but with distinct accent colors pass naturally (e.g. Cordovan's steel-blue accent vs Ember's orange-red accent: large accent ΔE → pass).
- Themes sharing primary and accent territory but with distinct muted colors pass naturally (e.g. Eventide's lavender muted `#8B84C4` vs Ember's warm brown muted `#9E8E78`: muted ΔE = 0.128 >> 0.07 → pass).
- Only themes where all three token pairs are genuinely close fail.

**Threshold:** `MIN_DIST = 0.07` (≈ 3.5 JNDs). Derivation:

| Threshold | Failures (54-theme collection) | Notes |
|---|---|---|
| 0.12 | 39 | Too high — flags visually distinct themes |
| 0.10 | 18 | Still flags pairs that look different |
| 0.08 | 4 | Better, but catches some borderline pairs |
| 0.07 | 2 | Only truly close pairs remain |
| 0.06 | 1 | Would miss espresso vs kiln (ΔE = 0.062) |

At 0.07, the two remaining failures are pairs where all three tokens are genuinely close in OKLab space and the themes share similar warm-amber or clay-red color territory. These are accepted as `KNOWN_CLOSE` legacy pairs.

**KNOWN_CLOSE entries (2, down from 35):**

| Pair | Max token ΔE | Weaker theme | Reason |
|---|---|---|---|
| `espresso\|kiln` | 0.062 | kiln (WCAG 4.53 vs 4.55) | Both warm clay-red darks; ceramic vs coffee concepts |
| `noir\|tallow` | 0.044 | noir (WCAG 4.66 vs 5.28) | Both warm amber darks; film noir vs candle concepts |

The weaker theme in each pair is noted for future consideration. Either theme could be removed or have its palette shifted to increase separation. No action is required immediately; both themes occupy distinct atmospheric concepts even if their palette coordinates are close.

## Consequences

**Positive:**

- KNOWN_CLOSE shrinks from 35 to 2 entries. Future contributors are far less likely to need an exception.
- The metric is perceptually meaningful — hue, saturation, and lightness differences all count. Near-grey and vivid colors at the same hue angle are correctly treated as different.
- Checking three tokens simultaneously means themes with a shared primary hue territory but divergent accent or muted naturally pass without exceptions.
- The error message reports ΔE values for all three tokens and notes the weaker theme when reviewing a failing pair.

**Negative:**

- OKLab is less intuitive to hand-calculate than hue angle. Contributors cannot easily verify the check without running `npm test`. The CONTRIBUTING.md note and this ADR provide enough context for contributors to understand what the test is doing, even if they cannot compute it mentally.
- `MIN_DIST = 0.07` is relatively permissive. Two themes could differ by 3.5 JNDs in all three checked tokens and still pass, even though they might look similar in a side-by-side comparison. The hue territory table in CONTRIBUTING.md remains the primary human-readable guard; the automated test is a backstop for near-copies, not a substitute for design judgment.
