# ADR-006 — Prompt layout: two-line-box vs single-line

**Status:** Accepted

## Context

The gloam prompt architecture supports two distinct layout variants for the Starship configuration:

- **two-line-box**: The prompt spans two lines. Line 1 contains all information modules (username, directory, git, languages, performance, fill, time) enclosed with curved box-drawing characters `╭` and `╰─`. Line 2 contains only the prompt character (`❯`, `⟫`, etc.).
- **single-line**: The prompt occupies a single information line followed by the prompt character on a second line, but without any box-drawing enclosure. The `╭` / `╰─` box frame is absent.

Both layouts use the same module order, the same token assignments, and the same two physical lines (information row + prompt character row). The distinction is purely whether the curved box frame is present.

## Decision

Each theme independently selects its layout variant as part of its design concept. The `prompt.layout` field in the theme JSON is `"two-line-box"` or `"single-line"`. The Starship generator produces the correct format string based on this field — no other configuration change is required.

The choice of layout is driven by the **conceptual framing** of the theme:

- **two-line-box** is used when the theme concept implies an enclosed or structured space: a stall, a framed view, a container with edges. The box characters `╭` and `╰─` read as a visual frame that encloses the prompt information.
- **single-line** is used when the theme concept implies open, unenclosed space: a horizon, an altitude, an open sky. The absence of the box reads as expanse — there is no edge to contain what you are looking at.

## Consequences

**Positive:**

- The layout choice is fully encapsulated in one JSON field and one generator branch. Adding a new theme with either layout requires no generator changes.
- The conceptual mapping (enclosed concept → box, open concept → no box) gives contributors a clear decision criterion. The layout is not aesthetic preference — it follows from the atmospheric concept.

**Negative:**

- Two similar themes may use different layouts based on their concepts (e.g., Parchment vs Daybook: both are warm light themes on paper, but Parchment uses single-line and Daybook also uses single-line because both are "open page" concepts). The visual difference between layouts is significant but the decision can be subtle.
- The `╭` / `╰─` characters require a Nerd Font or a font with Unicode box-drawing character support. On systems without the correct font, these render as replacement characters. Single-line themes degrade more gracefully on minimal fonts.

**Documentation:** New contributors choosing a layout should consult this ADR and the atmospheric concept description of the theme they are creating. If the concept implies an enclosed or bounded space, use `two-line-box`. If it implies open or expansive space, use `single-line`. See also ADR-007 for light-theme-specific constraints that apply to both layouts.
