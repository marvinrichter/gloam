# ADR-003 — Generator architecture over manual per-format files

**Status:** Accepted

## Context

gloam supports 11 target formats (Starship, iTerm2, Alacritty, Kitty, WezTerm, Ghostty, Windows Terminal, VS Code, Neovim, IntelliJ, Zed). With 18 themes, that is 198 output files. These files must stay in sync with the theme's semantic token values.

Two approaches were considered:

1. **Manual per-format files** — each theme's 11 format files are hand-written alongside the JSON source.
2. **Generator architecture** — a single `<name>.json` source of truth; all 11 format files are generated by running `npm run generate`.

## Decision

The generator architecture. Each theme has exactly one source-of-truth file (`themes/<name>/<name>.json`). All 11 format files are produced by pure-function generator modules in `scripts/generators/`. The `npm run generate` script runs all generators for all themes and writes the output files.

## Consequences

**Positive:**

- A single token change propagates to all 11 formats with one command.
- Format files cannot diverge from the source: the CI `git diff --exit-code` check enforces this.
- Adding a new target format requires writing one new generator module, not 18 hand-written files.
- Generator logic can be unit-tested independently of real theme data.

**Negative:**

- Contributors must run `npm run generate` after any JSON change. This is documented in `CONTRIBUTING.md` and enforced by CI.
- Format-specific quirks (e.g. Starship TOML structure, IntelliJ XML schema) are encoded in generator modules rather than being visible in the output files directly.
- A generator bug affects all 18 themes simultaneously.
