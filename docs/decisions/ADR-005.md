# ADR-005 — ANSI palette: visual harmony over role-name correctness

**Status:** Accepted

## Context

The 16-color ANSI palette (slots 0–15) has conventional role associations: slot 1 is "red", slot 2 is "green", slot 12 is "bright blue", slot 13 is "bright magenta", and so on. Some tools — `man` page renderers, file managers, system monitoring tools — assign specific ANSI slot numbers to display roles and expect the corresponding color family to be present (e.g. they assign status indicators to "bright green" slot 10 and expect something that reads as green).

The alternative approach is to treat ANSI slots as a palette of 16 values and assign them by visual harmony with the theme's semantic tokens, without regard for the conventional role name.

## Decision

gloam assigns ANSI slots by visual harmony with the theme's semantic tokens. The semantic tokens (`primary`, `accent`, `muted`, `error`) are mapped to specific ANSI slots that complement them perceptually, not by matching the slot's conventional color family name.

For example: a theme with a teal primary token may place a teal-adjacent color in slot 12 ("bright blue") because it harmonizes with the primary, even though strict ANSI semantics would expect a blue-family color there.

## Consequences

**Positive:**

- Syntax highlighting in editors (VS Code, Neovim, IntelliJ) and terminal emulators looks harmonious because ANSI colors are derived from the same palette as the semantic tokens.
- No visual "break" between prompt colors and syntax colors — the ANSI palette is a continuous extension of the four-token system.

**Negative:**

- Tools that use ANSI colors by role name rather than by index — certain `man` renderers, `ls` color rules, system dialog colors — will display unexpected colors. A "bright yellow" slot may contain the theme's muted token value if that assignment harmonizes better.
- This is a known and accepted trade-off. gloam is primarily a Starship prompt and editor syntax theme. In those contexts, colors are addressed by index and the visual harmony approach is strictly better.

**Documentation:** Each theme's design guide (`themes/<name>/<name>.md`) documents the ANSI design logic for that specific theme, explaining which slots are mapped to which semantic roles and why. The `ANSI Palette` section in each guide is the per-theme reference.
