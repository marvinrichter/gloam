# ADR-004 — Per-theme directories (not per-format)

**Status:** Accepted

## Context

With 18 themes and 11 formats, the 198 output files need to be organized somewhere. Two directory structures were considered:

1. **Per-format directories** — `themes/alacritty/<name>.toml`, `themes/vscode/<name>.json`, etc.
2. **Per-theme directories** — `themes/<name>/alacritty.toml`, `themes/<name>/vscode.json`, etc.

## Decision

Per-theme directories. Each theme lives entirely under `themes/<name>/` — source JSON, design guide markdown, and all 11 generated format files together.

## Consequences

**Positive:**

- `npx github:marvinrichter/gloam <theme> <target>` discovers any theme without a registry: it lists subdirectories of `themes/`.
- All artifacts for a theme are co-located: adding, removing, or inspecting a theme is a single directory operation.
- Per-theme git diffs are clean: `git diff themes/eventide/` shows all changes to one theme.
- The design guide (`eventide.md`) lives next to the files it documents.

**Negative:**

- To view all Alacritty configs at once, you must `ls themes/*/alacritty.toml` rather than `ls themes/alacritty/`. This is a minor inconvenience for cross-theme format comparisons.
- Format-specific tooling that expects a directory of same-format files (e.g. Alacritty's built-in theme switcher pointing to a theme directory) requires a separate copy or symlink step not provided by the installer.
