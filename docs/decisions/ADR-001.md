# ADR-001 — Four semantic tokens (not ten or twenty)

**Status:** Accepted

## Context

A terminal theme needs to assign colors to prompt elements. The question is how many distinct semantic roles to define. Prior art varies widely: some theme systems define 20+ named roles (background, foreground, selection, comment, keyword, string, number, …); others use raw hex values with no semantic layer at all.

## Decision

gloam exposes exactly four semantic tokens per theme: `primary`, `accent`, `muted`, `error`.

These map to the three functional zones of a terminal prompt plus one exception state:

- `primary` — navigation (directory path, language badges)
- `accent` — state and action (git branch, prompt character, cursor)
- `muted` — chrome (username, time, box corners, structural separators)
- `error` — exception (failed exit status only)

## Consequences

**Positive:**

- The assignment rule is learnable in one sentence: "muted for chrome, primary for navigation, accent for git and the cursor."
- Porting a theme to a new target format (VS Code, Neovim, IntelliJ) requires mapping four values, not twenty.
- The constraint forces each theme to derive colors from its concept rather than assigning one-off values to minor roles.
- New contributors can evaluate a theme's internal consistency with a small checklist.

**Negative:**

- Four tokens cannot express every syntax distinction a fully custom editor theme would support. gloam themes are intentionally prompt-first; editor syntax is approximate.
- Themes where the accent naturally reads as more visually dominant than the primary (e.g. Sable, where gold outweighs silver) require a documented override note rather than a mechanical role reassignment. See `themes/sable/sable.md`.
