# ADR-002 — WCAG AA 4.5:1 contrast as the baseline

**Status:** Accepted

## Context

Terminal themes can be designed for aesthetics, for accessibility, or for both. Many popular themes fail WCAG contrast requirements, sometimes severely. gloam needed to decide whether to treat contrast as a constraint or as a desirable property.

## Decision

Every semantic token (`primary`, `accent`, `muted`, `error`) in every theme must achieve ≥ 4.5:1 contrast ratio against its theme's background. This is the WCAG 2.1 Level AA threshold for normal text. It applies without exception — no token is granted a lower threshold for aesthetic reasons.

## Consequences

**Positive:**

- Themes work on calibrated and uncalibrated displays, at a range of brightness settings (200–300 nits typical), and across common display conditions.
- A contributor adding a new theme has a clear, machine-verifiable acceptance criterion.
- The baseline is compatible with real accessibility requirements without creating a "accessibility edition" separate from the aesthetic edition.

**Negative:**

- Some conceptually correct color choices (e.g. very pale muted tokens, or pastel accents) are excluded because they cannot pass 4.5:1 at a useful brightness level. The design space is constrained.
- Light themes are harder to design under this constraint because all tokens must be dark enough against a light background. The three light themes (Parchment, Daybook, Cirrus) required more iteration than the dark themes.

**Why not 3:1?** The 3:1 threshold is WCAG AA for large text (18px+ bold). Terminal text is typically 12–14px non-bold. 3:1 at that size is perceptibly insufficient — the 4.5:1 threshold was chosen because it consistently reads at terminal sizes across typical display conditions.
